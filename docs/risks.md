# Material risks

Status: proposed risk register for the plan. Each risk names a trigger that would make it real, the mitigation already built into the plan, and the issue that owns it. None of these risks is a prediction; they are the failure modes the plan deliberately works against.

| Id | Risk | Trigger | Mitigation | Owner issues |
|---|---|---|---|---|
| R-01 | The runtime host is chosen on opinion rather than evidence, and a later change invalidates work built on it | Host decision made without the measured comparison or without a recorded architecture decision record | A01 owns a benchmark spike against one fixed scenario and a decision record; A02 keeps contracts transport-neutral | A01, A02 |
| R-02 | Account mix-up: a read or draft silently uses a different account than the user chose | Tokens stored per tool instead of per account; account inferred from context | Per-account OAuth with Keychain storage; explicit account for send and commit; account mix-up is a named adverse test | C01, C16, F10 |
| R-03 | Prompt injection through mail, chat or tool results causes an unauthorized effect | Untrusted content instructs the model to send, delete or change a grant | Reasoning and tool text never create authority; draft-only default; broker checks grants at dispatch; injection containment tests | C16, C12, A07 |
| R-04 | A dispatched action has an unknown outcome and is misreported as canceled or repeated | Cancellation after dispatch, or a timeout with no response | Receipts, explicit unknown-outcome state, reconciliation before any retry, undo as a compensating action | A08, A05 |
| R-05 | A resolved, cancelled or forgotten item resurrects from stale retrieval | Background extraction or cache replay reopens a closed item | Suppression overlays consulted before planning; correction and forgetting track projections; stale-resurrection adverse test | B08, D03 |
| R-06 | Google OAuth policy blocks the intended distribution model | Verification requirements, the 100-user cap on unverified apps, restricted-scope assessment, or refresh-token expiry in testing status | Per-installation client in the user's own project, published unverified, with the cap and warning disclosed; verification is a named future step | C02, C15, F10 |
| R-07 | Restricted-scope content reaches a hosted inference route without an assessment | Egress rule absent or over-permissive for a data class | Route-class gate on first egress of a data class; operator verifies provider terms; the local model does not settle the question by itself | C15, F10 |
| R-08 | An always-listening feature ships without honest energy or privacy evidence | Wake phrase or continuous capture enabled before measurement | F14 gated on a measured energy delta under the proposed ceiling; no claim of Focus bypass or perfect privacy | F14, A18 |
| R-09 | The companion promises proactive work while the Mac sleeps | Copy or design implies overnight execution | Nothing executes or sends while the Mac sleeps; the companion queues with an honest message; Q-08 keeps the always-on host open | F16, F17, D18 |
| R-10 | Public distribution stalls on signing, notarization or update identity | Stage B needs an owner and a spending decision | Stage A ad-hoc pilot is the M1 target and is explicitly not claimed as frictionless public install; Stage B is a separate decision | F15 |
| R-11 | Provider change silently alters the egress or retention posture | Provider or route changes after a grant | Provider change re-opens the egress gate for the affected class; A06 keeps providers replaceable and budgets configured | C15, A06 |
| R-12 | Harness integration overstates its authority | Adapter tries to steer or cancel without a harness-granted contract | Observation-only until a scoped contract exists; no direct state writes, no global override; A11 owns the boundary | A11 |
| R-13 | Same-user process isolation is overclaimed | Risk surface described as isolated because a helper process runs separately | The plan states that a process split is an authorization chokepoint, not isolation, and that broad local control carries residual risk | A13, F12 |
| R-14 | Private code, prompts or fixtures leak into the public repository | Reuse or copy without licence review; residual personal data in examples | No reuse assumption; per-component licence and notice review; synthetic identities; the planning validator scans for private shapes and the reviewer judges content | A01, B12 |
| R-15 | Memory grows without bound or retention expectations are unstated | Consolidation and retention rules unmeasured | Consolidation, retention and inspector work in B10 and B15; raw audio defaults to discard after transcript confirmation | B10, B15, B09 |
| R-16 | Performance and battery claims are made without measurement | Documentation or copy quotes the proposed budgets as achieved | Budgets are labelled proposed; A18 builds the measurement harness and makes a breach visible; no figure is quoted as measured until recorded | A18 |
| R-17 | The plan drifts from the issues it publishes | Documents and backlog edited independently | The validator checks counts, ids, graph, labels and links; the issue map ties stable IDs to published numbers; the reviewer checks the exact SHA | integration (P00) |
| R-18 | Optional integrations become hidden requirements | A loop silently depends on Lux, harness or Trello being configured | Optional adapters degrade to not configured; the first slice acceptance runs with none configured; standalone install is an acceptance scenario | B06, C13, D15, F10 |
| R-19 | Urgent interruption copy promises more than the platform allows | Marketing or UI text implies bypassing Focus or guaranteed delivery | Interruption policy owns the classes; copy claims are bounded by the entitlement actually available; display is not treated as seen | D10, F09 |
| R-20 | The first slice grows until it cannot ship | Scope pressure adds send, delete, wake word or public distribution to M1 | The first slice is fixed in the roadmap and acceptance documents, with what it deliberately excludes named | P00, F10, D06 |
| R-21 | A model call reaches a provider before its route policy resolves | A new data class, provider path or tool is added without passing the entry gate | A06 is the single safe model-call entry and default-denies while policy is missing; completion of source-content cloud paths waits for C15; egress refusal is an acceptance scenario | A06, C15 |
| R-22 | An expired or revoked grant leaves stale silent data or a dead account | Token expiry, user revocation, or a testing-status refresh-token expiry | C02 stops ingestion for the account and shows the coverage gap and reauthorization state; C17 propagates revocation; scenarios S11 and S12 cover it | C02, C17 |
